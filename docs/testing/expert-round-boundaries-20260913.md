# Expert 单轮硬边界与内核生命周期修复

## 实现范围

使用现有 Deep Agents / LangChain 图和中间件，不另建调度器或科学状态机。
接口依据：[LangChain custom middleware](https://docs.langchain.com/oss/python/langchain/middleware/custom)。

- 每次 Expert 工作轮最多 60 次有效模型调用；同一次 DeepAgents run 从 48 次进入“已有证据只读、指定 report.md 可写”的收尾阶段，并预留最后一次无工具交付调用。
- 摘要及摘要修复占用同一配额。API 超时和其他可重试提供方故障退还配额，但保留次数、耗时及可用用量记录。重试发生在原请求，不重放工具。
- 通过真实模型开始回调计数。恢复同一工作轮、审核后的自动修正从已有记录继续计数；Coordinator 显式跟进创建新工作轮并保留专家线程/内核。
- 收尾阶段通过 DeepAgents/LangChain 原生 model middleware 限制模型可见工具；最后一轮完全无工具。空文本、截断、原始工具标记或工具调用不冒充交接。
- 相同归一化执行错误出现三次（原始错误加两次修复尝试）后转交障碍。签名保留异常类型、脚本/函数和错误信息，忽略动态执行 ID、行号及易变数值。这是近似的错误族识别，不是科学判断。
- 审核要求修改而作者额度已经耗尽时，将原报告与审核问题交回 Coordinator，不再重开作者并用配额占位文本覆盖报告。
- 作者报告保存后发出“author_complete / review pending”事实通知；不把它标成审核通过。

## 作者与审核者的 Python 内核一起修复

它们共用 `KernelPool`。每秒等待检查内核存活，执行中退出时保存已收 stdout/stderr 并返回失败。再次调用可以启动新内核，同时明确提示内存丢失；不会自动重算旧代码。

普通 Python 异常与 `KeyboardInterrupt` 返回执行错误，仍存活的内核保留变量。用户取消销毁实际内核并传播取消。代码执行默认单次 300 秒，超时销毁内核，记录 `timed_out / wall_time` 并保存已捕获输出。执行时间限制不适用于 API 等待。底层显式 ResourceLimits 用于部署/测试配置；取消与内核存活检查不依赖其时间额度。

## 文件与数值操作

固定 outputs 目录保持不变，后台仍保留不可变执行快照。模型只收到新增/内容改变的输出文件路径；报告不再附加逐执行文件库存和全部执行 ID。报告中的实时文件引用绑定到可用的最新快照。

在已有 `oceanx_array_ops` 中补充缺测匹配分母的命名维度加权均值、明确秒/天分母转换及角度梯度转米制梯度。沿用既有维度/坐标精确对齐和逐列索引检查。测试覆盖数值答案、缺测、错轴、错坐标、越界和度/弧度一致性。没有新增必填表格，也没有把通用工具调用成功当成科学审核通过。

## 验证

65 项聚焦回归通过（79.37 秒），包括：

- 真实 LangChain 图中收尾工具不可执行，最后一轮能生成文本交接；非法交接不能通过。
- API 超时退还配额但保留失败计量；摘要及其修复计入同一额度。
- 同类错误计数、额度耗尽后审核路由、已有报告不被额度占位结果覆盖。
- 真实 sandboxed Jupyter 内核的变量保留、角色隔离、异常、KeyboardInterrupt、执行中退出、取消、超时和重新启动。
- 固定目录和快照不变，变化文件增量与报告去重。
- 真实本地 Agent Server + 确定性模型的通知、同线程跟进、审核和故障链。测试模型对 pending 通知等待，不把作者交稿误认审核结束。

这些验证证明执行边界和交接管道，并不证明真实模型的研究判断已经改善，也不证明 Research Tree 有因果收益。未重启 Campeche 完整研究测试。

独立真实 API 小问题探针：`scripts/probe_expert_round.py`。使用生产 Expert 构建、工具、计量和默认配额，但在进程内播种测试宿主，不启动 Coordinator/审核。前两个启动尝试在调用模型前失败（测试脚本导入与请求 ID），未作为模型表现；保留痕迹，不覆盖旧研究任务。
