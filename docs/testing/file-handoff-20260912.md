# File handoff verification — 2026-09-12

## Implemented

- No model-facing shared evidence index. Each dispatch has a readable results folder
  and one `report.md`; `ocean_read_file` lists folders and reads text on demand.
- Generated result subfolders use ASCII role IDs plus a short suffix. The assigned
  question, including Chinese text, is preserved at the start of `report.md` rather
  than in the directory name. Existing input paths and user directories are untouched.
- Saved arrays and code are available read-only to authorized task peers, including
  later requests. Private workspaces/logs and unassigned sources remain inaccessible.
- A reviewed correction becomes the same public report. The internal journal keeps
  the original author and repair rounds; response correlation no longer rewrites the
  producing round's ID. Neither the Coordinator nor another Expert selects versions.
- The original user request is included in delegation context. Literature acquisition
  preference no longer supplies a research delegation/presentation checklist.
- Existing per-Expert review timing, dataset context cache, desktop events, and
  publication remain in place. Public figure file paths can be published without
  recomputing them.
- Native-v4 model returns contain a short verbatim preview, report path and execution
  facts. Scientific content, limitations, review and file checks live in the report.
  Only a failed report save returns the unsaved content inline to prevent data loss.
- Continuation instructions no longer forbid recomputation. Literature instructions
  retain paper-selection inputs but not the per-paper presentation template.
- ASCII suffixes are the first six hexadecimal characters of a work-order ID hash,
  generated by the backend, not a model-written English title. They prevent collisions,
  not summarize the question: the role is readable, the question is in `report.md`.
