# 后端分配路径、文件交接：2026-09-14

## 已实现

- 后端按原生 Expert thread 分配固定目录：作者为 `report.md`，审核者为自己的 `review.md`。续跑保留相同路径，在模型开始工作之前注入提示词；原生委派接口没有新增字段。
- 可写文件的 Expert 使用原生文件工具保存报告，然后正常结束。`ocean_deliver` 不再注册给 Expert。后台读取指定文件，不解析最终回复里的路径，也不把“Done”重建成报告。
- 只读讨论角色和无工具收尾调用由后台将最终文本写入同一指定路径；没有新增模型调用。收尾阶段保留原生文件写入工具，仍禁止新增代码执行。
- 执行错误只进入执行记录和错误通知，不写入报告；失败续跑保留既有报告。没有文件、空文件、符号链接分别按文件事实处理，不生成假报告，不把旧内容当成失败续跑的新结论。
- 科学报告不加角色名、委派清单、运行状态、审核附录。标题由文件头读取；审核记录单独保存和打开。没有重新引入结果摘要字段。
- 同一任务内已有报告的读取不再依赖作者是否已标记完成，也不依赖重复的 input_refs 子集比较。任务/工作区隔离保留，审核者仍只读被分配的作者证据。
- 作者保存、审核进行中只推送界面快照，不启动 Coordinator。整条链结束或发生阻塞时发送路径、执行状态、审核状态和实际错误；不发送报告正文或审核全文。
- 复审期间不提前终结审核运行记录，避免下一次工具调用被拒绝。报告与审核文件提前保存，不等整条链结束。

## 验证

59 项单元/文件系统/持久内核/原生委派测试通过，覆盖：

- 指定文件优先于最后聊天文本、正常完成不重复写文件、失败保留报告、缺文件不生成占位文本。
- 无工具文本保存、报告不解析成旧结构化响应、独立审核文件、符号链接防越界。
- 运行中的已保存文件可读、跨任务拒绝访问、前端当前文件标题/分页读取。
- 固定执行目录、原生工具及持久 Python 内核、原有调用额度和 API 超时计量。

11 个真实本地 Agent Server + 原生 Deep Agents 集成场景通过（模型为确定性测试模型，不调用外部 API）：

1. 只读讨论角色交付，原生同会话续跑，服务器重启后恢复。
2. 写代码的 Expert 经原生文件工具保存并独立审核。
3. 审核要求修改 → 原作者修改原文件 → 复审 → 同会话新问题。
4. 模型执行失败，无假报告。
5. 报告保存失败，父任务收到错误而非无限等待。
6. 桌面 WebSocket 全链路及报告读取。
7. 长中文报告不进入快照正文，文件内容不丢失。
8. 界面推送失败不影响审核和交付。
9. 第一轮已有有效报告，第二轮失败，路径及原报告保留。
10. 模型声称完成但未保存，返回文件缺失。
11. 审核者执行失败，作者报告保留，明确未完成审核而非通过。

Coordinator 在集成测试中使用原生 `read_file` 读取通知中的实际报告路径；普通两轮工作只收到两次完成通知，没有审核中间通知。作者报告第一行保持科学标题，最终聊天回复“Done”不会覆盖它。

首组 10 个集成场景用时 114.74 秒，补充审核故障场景 10.72 秒；这些是本地工程测试耗时，不是研究性能结果。尚未重跑真实 DeepSeek 研究 query，不能据此宣称科学质量、研究树效果或 token 降幅已验证。此前长测及监控没有重启。
